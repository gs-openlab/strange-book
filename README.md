# 奇怪的书

纳新题第 7 题的作答。题目给出了一门只有 8 个关键字、结构与 Brainfuck 完全同构的语言，
并留下三道任务。

- `booklang.py` —— 这台机器的解释器（支持逐指令跟踪、末态导出、括号模型切换）
- `programs/` —— 题面三道任务的程序原文
- `verify.py` —— 自检脚本，先验已知答案的经典程序，再跑三道题
- `run.log` —— `verify.py` 的完整输出（可直接复现，见文末）

---

## 1. 语言与执行模型

### 1.1 关键字

| 符号 | 含义 |
| --- | --- |
| `+` | 指针所指单元值 +1 |
| `-` | 指针所指单元值 −1 |
| `>` | 指针向右移动一格 |
| `<` | 指针向左移动一格 |
| `[` | 若指针所指单元值为 0，跳转到**向后最近的** `]` 位置 |
| `]` | 若指针所指单元值非 0，跳转到**向前最近的** `[` 位置 |
| `.` | 输出指针所指单元的值，作为 ASCII 值对应的字符 |
| `,` | 输入一个字符，将其 ASCII 值赋给指针所指单元 |

单元数量不限（本解答按"用到哪格才建哪格"处理），初值全为 0，取值 0–255、超出即回绕；
指针初始指向 0 号单元。

### 1.2 关于括号语义的一点说明

题面对 `[` 与 `]` 的描述都是"**跳转到括号所在位置**"，而非"跳到括号之后"。这两种写法
其实等价：跳转发生时被跳到的那个括号其条件必然已为假（否则不会发生跳转），所以落到该括号
上会立刻再次判定失败、顺势执行下一条指令。换言之，字面语义只比"跳到括号之后"多花一次
判定。

为把两种模型都跑通、并确认它们产出完全一致，解释器提供 `-b literal` 开关；`verify.py`
第二节对两道题各三种输入做了对比，结果全部相同。

### 1.3 与 Brainfuck 的对应

本语言与 Brainfuck 的 8 个指令（`><+-.,[]`）逐条同构，区别仅两点：一是本题未规定单元
数量与输入耗尽的处理，二是指针左移越界在题面中未定义。故 `booklang.py` 的语义正确性
可以直接用已知答案的经典 Brainfuck 程序验证（`verify.py` 第一节）。

## 2. 第一页

程序原文（`programs/page1.book`）：

```
,[
>+
<-
]
>-.
```

### 2.1 它做了什么

1. `,` 读入一个字符，其 ASCII 值存入 0 号单元。
2. `[` 判断 0 号单元是否为 0：
   - 若为 0（即输入的就是 ASCII 0），直接跳过整个循环体；
   - 否则进入循环体。
3. 循环体 `>+<-` 依次是：指针右移一格、把 1 号单元加 1、指针回到 0 号单元、把 0 号
   单元减 1。于是**每执行一轮，0 号单元减 1、1 号单元加 1**，两格之和不变。
4. `]` 判断 0 号单元是否非 0：非 0 就跳回 `[` 继续。循环在 0 号单元被减到 0 时结束。
   此时 1 号单元恰好等于最初读入的 ASCII 值——这个循环相当于把 0 号单元的值整体
   "搬运"到 1 号单元。
5. `>-` 指针移到 1 号单元，把它的值**减 1**。
6. `.` 把 1 号单元的值作为 ASCII 码输出。

所以这道程序的功能是：**读入一个字符，输出 ASCII 码比它小 1 的那个字符**。前提是
输入不为 ASCII 0：输入 0 时循环体被整体跳过，1 号单元保持 0，减 1 后回绕成 255，输出
的是码值 255 的字符。

### 2.2 执行过程示例（输入 `A`，ASCII 65）

| 步 | 指令 | 指针 | 当前单元 | 非零单元 |
| --- | --- | --- | --- | --- |
| 1 | `,` | 0 | 65 `'A'` | 0:65 |
| 2 | `[` | 0 | 65 | 0:65 |
| 3–6 | `>+<-` | 0 | 64 | 0:64, 1:1 |
| 7 | `]` | 0 | 64 | 0:64, 1:1 |
| 8–11 | `>+<-` | 0 | 63 | 0:63, 1:2 |
| … | 循环体共执行 **65** 轮（至此累计 327 步） | | | |
| 328 | `>` | 1 | 65 | 0:0, 1:65 |
| 329 | `-` | 1 | 64 `'@'` | 0:0, 1:64 |
| 330 | `.` | 1 | 64 `'@'` | 输出 `'@'` |

### 2.3 答案

功能：**输出输入字符 ASCII 码减 1 所对应的字符**。

| 输入 | 输入 ASCII | 输出 | 输出 ASCII |
| --- | --- | --- | --- |
| `A` | 65 | `@` | 64 |
| `C` | 67 | `B` | 66 |
| `Z` | 90 | `Y` | 89 |
| `1` | 49 | `0` | 48 |
| `\x00` | 0 | 码值 255 | 255（0 减 1 回绕） |

按题目要求的记号，取一例作答：**`{C(67), B(66)}`**。

## 3. 第二页

程序原文（`programs/page2.book`）：

```
++++++++++
[
>++++++++
>++++++++
<<-
]
>-.
>.
```

### 3.1 各符号在做什么

| 片段 | 作用 |
| --- | --- |
| `++++++++++` | 0 号单元累加到 **10**，作为循环计数器 |
| `[` | 计数器（0 号单元）不为 0 时进入循环 |
| `>++++++++` | 指针右移到 1 号单元，把它加 **8** |
| `>++++++++` | 指针再右移到 2 号单元，把它加 **8** |
| `<<-` | 指针左移两格回到 0 号单元，把计数器减 1 |
| `]` | 计数器仍非 0 就跳回 `[`，共循环 **10 轮** |
| `>-` | 指针移到 1 号单元，减 1 |
| `.` | 输出 1 号单元的值 |
| `>.` | 指针移到 2 号单元，输出它的值 |

循环结束后：0 号单元 = 0，1 号单元 = 8 × 10 = **80**，2 号单元 = 8 × 10 = **80**。
这个循环是一个"倍乘器"：外层计数器每减 1，内层两个单元各加 8，于是 10 次循环把 8
累加了 10 倍。

随后把 1 号单元减 1 得到 **79**，先输出它，再输出 2 号单元的 **80**。

顺带一提，80 恰好是 `'P'` 的 ASCII 码、79 恰好是 `'O'`——题目用 `++++++++`（8）乘
`++++++++++`（10）凑出 80，再把其中一个减 1，于是这段程序打印出的正是 `OP`。

### 3.2 执行末尾（跟踪摘录）

```
步 231  ip=32  指令 ]  ptr=0  当前单元 0           非零单元 1:80 2:80
步 232  ip=33  指令 >  ptr=1  当前单元 80          非零单元 1:80 2:80
步 233  ip=34  指令 -  ptr=1  当前单元 79          非零单元 1:79 2:80
步 234  ip=35  指令 .  ptr=1  当前单元 79 ('O')    非零单元 1:79 2:80
步 235  ip=36  指令 >  ptr=2  当前单元 80          非零单元 1:79 2:80
步 236  ip=37  指令 .  ptr=2  当前单元 80 ('P')    非零单元 1:79 2:80
```

### 3.3 答案

程序先构造出两个 80（= `'P'`，恰好是 8 × 10），再把其中一个减 1 拿到 79（= `'O'`），
按 `'O'`、`'P'` 的顺序输出。输出结果为：

**`OP`，即 `{O(79), P(80)}`。**

## 4. 第三页

题目：用这门语言编写程序，读入两个字符，输出这两个字符的 ASCII 值**之和**所对应的字符，
并假设所有 ASCII 码表中的字符皆可输入。

### 4.1 程序（`programs/page3-sum.book`）

```
,>,<[->+<]>.
```

全文只有关键字，不含任何其他字符。

### 4.2 它做了什么

1. `,` 读入第一个字符，存入 0 号单元。
2. `>` 指针移到 1 号单元。
3. `,` 读入第二个字符，存入 1 号单元。
4. `<` 指针回到 0 号单元。
5. `[->+<]` 把 0 号单元的值整体加到 1 号单元上（每轮 0 号减 1、1 号加 1，0 号归零时
   退出），于是 1 号单元 = 第一个字符 + 第二个字符，0 号单元 = 0。
   若第一个字符为 ASCII 0，`[` 判定为假、循环体被跳过，1 号单元保持第二个字符本身，
   结果同样是"两者之和"。
6. `>.` 指针移到 1 号单元并输出其值，即输出"两字符 ASCII 值之和"对应的字符。

### 4.3 溢出说明

单元取值 0–255、超出即回绕，故两字符之和超过 255 时会按 256 取模。若两个字符都在
标准 ASCII 范围（0–127）内，和为 0–254，不会回绕；只有在输入含扩展字符（128–255）时
才会发生，例如 `\xff` + `\xff` = 510，回绕后输出码值 254 的字符。

### 4.4 验证

`verify.py` 第五节给出示例：输入 `AZ`（65 + 90 = 155）输出码值 155 的字符，这正是题面
示例 `{A(65), Z(90)}` 所指的那个和。第七节进一步穷举了 **256 × 256 = 65536** 组输入，
输出全部等于"两输入之和 mod 256"，无一组不符。

用 `od` 可以看到输出确实是单个字节、没有被 UTF-8 重编码：

```
$ python3 booklang.py programs/page3-sum.book -i AZ | od -An -tu1
 155
$ python3 booklang.py programs/page3-sum.book -i AB | od -An -tu1
 131
$ python3 booklang.py programs/page3-sum.book -x ffff | od -An -tu1
 254
```

码值 155、131、254 在终端上都不是可见字符（155 是制表控制符 CSI，254 属于 Latin-1
扩展区），所以这里给出十进制码值而非字形。

## 5. 复现方式

```
cd strange-book
python3 verify.py                                 # 完整自检 + 三道题，输出见 run.log
python3 booklang.py programs/page1.book -i C -t   # 第一页，输入 'C' 并逐指令跟踪
python3 booklang.py programs/page2.book -d        # 第二页 + 末态
python3 booklang.py programs/page3-sum.book -i AB # 第三页，输入 'A' 'B'
python3 booklang.py programs/page1.book -x 00 -d  # 输入 ASCII 0（不可见字符用十六进制给）
```

`booklang.py` 的用法：程序文件之后可加 `-i`（字符输入）、`-x`（十六进制输入）、`-t`
（逐指令跟踪）、`-d`（末尾状态）、`-s`（步数上限）、`-b`（括号模型）。
程序输出走 stdout，**按单字节原样写出**（故码值 128–255 不会被 UTF-8 重编码）；跟踪与
末态走 stderr，因此 stdout 可以直接管道给 `od`、`xxd` 等工具。
